# Shipout v0.13.0 spec: timeout checks

## Why
Of the backend concepts vibe coders actually need, timeouts are the most
common production embarrassment: one slow API hangs every request and the
whole app freezes. Shipout v0.13.0 teaches this with a check plus a fix,
in plain language, the same way it teaches security headers.

## What it does
New command: `shipout review [path]`

Walks the project's JavaScript and TypeScript source and flags outbound
HTTP calls with no timeout:

- `fetch(url)` or `fetch(url, {...})` with no `signal` in the options
- `axios.get/post/...(url)` or `axios.create({...})` with no `timeout`
- `http.request` / `https.request` / `http.get` with no `timeout` option

Findings carry a confidence note. A call with no options argument, or an
inline options object with no timeout, is a definite finding (MEDIUM).
A call whose options are a variable Shipout cannot see into is reported
as INFO: "could not verify, check manually". No guessing, no false
positives.

`shipout review [path] --fix` generates `timeout-helper.js` in
`./shipout-fixes/`, adapted to the detected framework (Express, Next.js,
Fastify, Koa, plain Node): a `fetchWithTimeout` helper built on
`AbortSignal.timeout`, an axios instance with a timeout set, and
framework specific server timeout wiring.

## What it does not do
- It does not probe timeouts over the network. You cannot detect a
  missing timeout from outside the code, so this check reads source.
- It does not flag what it cannot verify. Variable options produce INFO,
  not MEDIUM.
- Node `http` calls in a file that uses `req.setTimeout` are INFO, since
  the timeout may be applied after the request is created.

## Exit codes
Exits 1 when any MEDIUM or higher finding exists, so it works in CI.
Exits 0 when clean or INFO only.

- `go/scanner/timeout.go` — `CheckTimeouts(dir string) []Finding`
